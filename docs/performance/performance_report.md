# CANN 分布式通信性能测试报告

## 1. 测试环境
- 平台：模拟器（PureSim 模式）
- 节点配置：单节点 8 NPU（昇腾 910B）/ 多节点 2×8 NPU
- 链路参数：HCCS 100 GB/s（延迟 0.001ms）、ROCE 25 Gbps（延迟 0.005ms）

## 2. 测试方法
- 基准测试框架：自定义 C++ 基准测试（bench_comm）
- 数据规模：1KB、64KB、256KB、1MB、16MB、64MB
- 测试模式：单节点（8 ranks）、多节点（2×4 ranks）

## 3. 单节点测试结果（8 ranks）

### 3.1 AllReduce 性能对比
| 数据规模 | Ring | RHD | Pipeline |
|---------|------|-----|----------|
| 1 KB | 0.93 ms | 0.69 ms | 1.12 ms |
| 64 KB | 1.23 ms | 1.07 ms | 1.45 ms |
| 256 KB | 2.85 ms | 2.41 ms | 3.12 ms |
| 1 MB | 7.70 ms | 6.93 ms | 8.25 ms |
| 16 MB | 100.94 ms | 117.28 ms | 105.32 ms |
| 64 MB | 398.52 ms | 465.18 ms | 412.67 ms |

### 3.2 AllGather 性能对比
| 数据规模 | Ring | Butterfly |
|---------|------|-----------|
| 1 KB | 0.85 ms | 0.52 ms |
| 64 KB | 1.15 ms | 0.89 ms |
| 1 MB | 6.92 ms | 5.45 ms |
| 16 MB | 89.23 ms | 72.15 ms |

### 3.3 分析
- **小数据（≤64KB）**：RHD/Butterfly 由于步数更少，延迟更低
- **中等数据（256KB-1MB）**：RHD 优势明显，步数减少带来的延迟降低超过通信量增加的影响
- **大数据（≥16MB）**：Ring 带宽利用率更高，RHD 每步通信量大导致总时间增加
- **Pipeline**：在中等数据上有轻微开销，大数据上接近 Ring 性能

## 4. 多节点测试结果（2×4 ranks）

### 4.1 AllReduce 性能
| 数据规模 | Ring | RHD |
|---------|------|-----|
| 1 KB | 1.85 ms | 1.52 ms |
| 64 KB | 2.45 ms | 2.18 ms |
| 1 MB | 15.32 ms | 13.89 ms |
| 16 MB | 198.45 ms | 225.67 ms |

### 4.2 分析
- 多节点场景下 ROCE 带宽（25 Gbps）远低于 HCCS（100 GB/s）
- Ring 算法在大数据上表现更好，因为通信模式更适合异构带宽
- RHD 在小数据上仍有优势（步数少）

## 5. 理论性能分析
- Ring 带宽效率：(N-1)/N = 87.5%（8 ranks）
- RHD 步数优势：log2(8)=3 vs 8-1=7，步数减少 57%
- Pipeline 流水线深度：4 个 chunk 并行处理
- 瓶颈分析：模拟器中阻塞 recv 导致串行化，实机可能表现不同

## 6. 扩展性分析
- 2 ranks → 4 ranks → 8 ranks：Ring 步数从 2 → 6 → 14
- RHD 步数从 2 → 4 → 6，扩展性更好
- 多节点扩展：ROCE 带宽成为瓶颈，需要分层算法优化
