# CANN 分布式通信可靠性测试报告

## 1. 测试目标
验证通信算法在链路故障场景下的行为、容错能力和恢复机制。

## 2. 故障注入机制

### 2.1 FaultChannel 装饰器模式
使用装饰器模式包装 IChannel 接口，支持以下故障类型：
- **链路故障**：按概率触发，抛出 CannException
- **超时**：基于 timeout_ms 参数，按概率模拟超时
- **数据损坏**：按概率翻转数据位

### 2.2 流量控制
- `max_concurrent_sends`：限制并发发送数，防止网络拥塞
- 使用原子计数器和自旋等待实现
- 超出限制时发送操作阻塞直到有空闲槽位

### 2.3 超时重传
- `max_retries`：最大重试次数（默认 3）
- 发送/接收超时后自动重试
- 统计重试次数到 FaultStats.num_retries

## 3. 测试结果

### 3.1 链路故障测试
- 配置：link_failure_rate = 1.0（100% 故障率）
- 结果：所有 send/recv 操作正确抛出 CannException
- 统计：num_faults 正确累计

### 3.2 正确性验证（无故障）
- 配置：无故障注入
- 结果：AllReduce Ring 在 4 ranks 上正确计算 SUM(0,1,2,3) = 6.0
- 所有 rank 输出一致

### 3.3 概率性故障测试
- 配置：link_failure_rate = 0.5
- 结果：100 次 send 中约 50 次触发故障（统计验证通过）

### 3.4 流量控制测试
- 配置：max_concurrent_sends = 2
- 结果：并发发送数不超过 2，多线程场景下正确限流

### 3.5 超时重传测试
- 配置：timeout_ms = 0.8（80% 超时概率），max_retries = 5
- 结果：部分发送在重试后成功，num_retries 统计正确

### 3.6 精度漂移测试
- 配置：100 次迭代，固定输入
- 结果：FLOAT32 和 FP16 输出完全确定性，无精度漂移

## 4. 边界条件测试

### 4.1 小数据块
- count=1，4/8 ranks：AllReduce 正确
- count < nranks：回退到 all-to-all reduce，正确

### 4.2 大数据块
- 1MB 数据（262,144 floats）：AllReduce 正确，抽查验证通过

### 4.3 混合精度
- FLOAT32、FP16、BF16、INT32：所有数据类型 AllReduce 正确

## 5. 随机化测试
- 随机输入数据（-100 到 100），验证 AllReduce SUM 输出与期望值一致
- 相对误差容忍度：1e-5
- AllGather 随机化测试：验证每个 rank 收集到的数据与输入一致

## 6. 结论
- FaultChannel 装饰器模式有效隔离了故障注入逻辑
- 流量控制和超时重传机制工作正常
- 算法在无故障场景下保持正确性
- 混合精度支持完整，精度漂移可控
- 边界条件和随机化测试全部通过
